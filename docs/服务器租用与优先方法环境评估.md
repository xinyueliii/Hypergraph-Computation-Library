# HyperComp 服务器租用与优先方法环境评估

更新日期：2026-08-11。

## 一、直接结论

首台远程服务器建议租用以下配置：

- GPU：**NVIDIA RTX 3090 24 GB**，首选；同等级替代为 RTX A5000 24 GB；预算宽裕可用 A100 40 GB。
- CPU：至少 8 vCPU，建议 12–16 vCPU。
- 内存：至少 32 GB，建议 64 GB。
- 磁盘：至少 300 GB NVMe，建议 500 GB 可扩容数据盘。
- 系统：Ubuntu 22.04 LTS 主机。
- NVIDIA 驱动：535 或更高版本，优先使用服务商稳定镜像提供的 550 系列或更新驱动。
- 必要能力：SSH、`sudo` 或 root、Docker、NVIDIA Container Toolkit、可在容器内使用 `nvcc` 的 CUDA `devel` 镜像。
- 网络：能够访问 GitHub、Hugging Face、清华云盘；Google Drive 或百度网盘至少能访问其中一个，否则需要从本地上传 checkpoint。

这台机器用于**推理跑通、代码适配和少量 smoke test**，不按完整论文训练配置采购。当前没有必要租多卡服务器。

选择 RTX 3090 的核心原因不是单纯追求算力，而是兼容性已经得到多个上游项目的直接验证：SuperFast 官方声明在 CUDA 11.1 和 RTX 3090 上测试，E-3DTrack 也在 RTX 3090 上测试，Hyper-PCN 则在 RTX 3090 上训练。三者分别覆盖事件视觉、自定义 CUDA 扩展和点云任务。

## 三、为什么首选 3090，而不是 4090

RTX 4090 的速度更快，但不适合做这批旧事件项目的首台兼容服务器。SuperFast、E-3DTrack、E-HRSAI 和 THU-ERGB-SAI 都围绕 CUDA 11.1 / PyTorch 1.9 构建，而 Ada 架构从 CUDA 11.8 才开始获得工具链支持。直接把旧环境放到 4090 上，很容易遇到架构未编译、无可用 kernel image 或被迫升级整个旧依赖链的问题。

RTX 3090 属于 Ampere，官方项目已经实际验证 CUDA 11.1 路线，同时又有 24 GB 显存，能够兼顾现代检测、计数与点云任务。NVIDIA 的兼容性文档也说明新驱动能够运行由旧 CUDA Toolkit 构建的应用，因此主机可保持较新的驱动，各项目在容器中固定自己的 CUDA 用户态工具链。

如果服务商没有 3090，选择顺序建议为：

1. RTX A5000 24 GB。
2. A100 40 GB。
3. 其他 Ampere 24 GB 以上 GPU。
4. 4090 24 GB 仅用于现代环境；旧事件环境需要迁移到 CUDA 11.8/PyTorch 新版后再试。

不建议首选 16 GB GPU。它可能足以跑部分小样例，但 Count Anything、高分辨率事件成像和后续三维任务的显存余量太小，会把时间消耗在降分辨率和排查 OOM 上。

## 四、服务器上的环境划分

不为每个模型单独创建环境，而是在同一台服务器、同一份仓库和统一入口下优先复用两个版本化运行时：

| 环境 ID | 建议镜像/基础版本 | 组件 |
|---|---|---|
| `visual-cu121` | Ubuntu 20.04；Python 3.11；PyTorch 2.2.2；CUDA 12.1 runtime | DHG、HGNN、HGNN+、YOLOv13、Hyper-YOLO、SoftHGNN、Hyper-PCN |
| `count-anything-py311` | Ubuntu 20.04；Python 3.11；PyTorch 2.7.1+cu126 | Count Anything；共享环境冲突后保留 |
| `hypergraph-py310` | Ubuntu 22.04；Python 3.10；PyTorch 2.x | KHGNN |
| `lighthgnn-cu116` | Ubuntu 20.04；Python 3.9；PyTorch 1.12.1；CUDA 11.6 | LightHGNN / LightHGNN+ |
| `event-cu113` | Ubuntu 20.04；Python 3.8；PyTorch 1.10.0；Torchvision 0.11.1；CUDA 11.3；GCC 9 | E-HRSAI、E-3DTrack、MeshNet；后续兼容事件组件优先复用 |
| `cuda-12.1-toolchain` | 共享 CUDA compiler 12.1.105；约 184 MB | 供 `visual-cu121` 编译 Hyper-PCN 等兼容扩展；不是 Python 环境 |

统一入口根据组件清单调用指定环境，数据预处理、checkpoint 解析和推理脚本仍留在任务 adapter 内。worker 负责进程和导入隔离，并不自动意味着独立 Python 环境。只有复现实证冲突后才增加完整环境。

PVRNet 已通过现代推理兼容层复用 `visual-cu121`；不需要为当前集成另租 V100 或重建 CUDA 9。

## 五、租用页面应逐项确认

- [ ] GPU 型号是 RTX 3090 24 GB、RTX A5000 24 GB 或 A100 40 GB，不是共享显存或切分后的 vGPU 实例。
- [ ] 有完整 24 GB/40 GB 独占显存，允许长时间 CUDA 编译。
- [ ] 系统盘和数据盘合计至少 300 GB，最好 500 GB，并支持扩容或快照。
- [ ] 内存至少 32 GB，优先 64 GB。
- [ ] 提供公网 SSH 地址、端口、用户名和密钥/临时密码。
- [ ] 允许 `sudo` 或 root，允许安装 Docker 与 NVIDIA Container Toolkit。
- [ ] `nvidia-smi` 正常，驱动版本不低于 535。
- [ ] 能运行带 `nvcc` 的 CUDA `devel` 容器，而不只是 PyTorch runtime 镜像。
- [ ] 能访问 GitHub 和至少一种 checkpoint 下载来源。
- [ ] 支持关机保存磁盘或制作镜像，避免每次重配环境。

## 六、租到机器后的首轮验收顺序

1. 检查 GPU、驱动、磁盘、内存、Docker 和 NVIDIA runtime。
2. 拉取 HyperComp 仓库，建立服务器侧数据与 checkpoint 目录，不把大文件放进 Git。
3. 保留已验证的 SuperFast 旧版运行时，并复用 `event-cu113` 运行 E-HRSAI。
4. E-3DTrack 与 MeshNet 已取得合法可用资产并在 `event-cu113` 完成最小验证，没有克隆独立环境。
5. 后续事件组件先尝试 `event-cu113`，修改依赖后运行 `pip check` 和既有组件回归。
6. 复用 `visual-cu121` 和共享 CUDA 12.1 工具链编译 Hyper-PCN 扩展；该项已完成。
7. [已完成] 在共享环境复现冲突后创建 Count Anything cu126 环境，下载 checkpoint 并完成单图文本计数。
8. 把每个模型的环境 ID、命令、输入样例、峰值显存和运行产物写回组件清单与验证记录。

第一轮先按小时租用并完成环境构建、checkpoint 下载和最小样例。环境稳定后立即制作镜像或快照，再开始批量集成，避免持续为安装时间付费。

## 七、当前采购边界

- 当前目标是“有几个方法能从统一入口推理”，不是完整训练，所以**单卡 24 GB** 是合理起点。
- Count Anything 官方默认训练使用 4 GPU；如果后续真的要训练，再单独评估多卡，不应提前为此采购。
- 完整 CLOC、事件数据集和多套三维数据可能显著超过首轮样例所需空间。首轮只下载 checkpoint 和合法小样例；需要整库评测时再扩数据盘。
- 如果后续 Hyper-3DG 释放完整代码并需要三维生成训练，再重新评估 48 GB 显存或多卡；目前不纳入首台服务器预算。
